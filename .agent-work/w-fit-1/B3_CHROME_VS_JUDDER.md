# B3 — Does post-ascal chrome fix the user complaint, or only make judder sharp?

**Answer: chrome alone does NOT fix publish/display judder. It can make edges sharp while motion timing stays wrong. DROP chrome from this fit.**

## Mechanisms (RTL-separated)

| Path | What sets *when* a new picture appears | What sets *spatial* resolution |
|------|----------------------------------------|--------------------------------|
| **Content + today’s player chrome** | ARM `publishDdrFrame` → doorbell → `swap_pending` → **vsync** swap in `ddr_frame_store` (`vsync_pulse && swap_pending && pending_ready_s2`, ~303–317) → `frames_done++` on real swap | `present_core` `V_STORE=240` / `H_DE=529` → ascal upscale |
| **Post-ascal chrome plane (design c)** | Either (i) same bank-swap cadence if chrome is still painted into F1 (does **not** meet user), or (ii) its **own** DDR/line plane swapped on `hdmi_vs` / ARM chrome doorbell — **independent of content swap**, but still paced by **ARM paint/publish intervals** and HDMI refresh | Composited on `clk_hdmi` **after** ascal → **1:1 output pixels** |

## Why sharp ≠ smooth

1. **User complaint (low-res overlay)** is spatial: glyphs hit the 240-line store path (w-osd-hires T1: every product overlay ends in `publishDdrFrame` → `store_y`). Post-ascal plane **does** fix that **if** chrome is not in F1.

2. **Judder** parent measured is **temporal**:
   - publish-interval ACF lag1 = −0.1950 (ARM publish spacing)
   - display hold histogram equal-adjacent ~15–30% (latch/hold pattern)
   - Neither is generated by ascal bilinear soft edges.

3. **If chrome is updated from the same ARM present/publish loop** that feeds F1 (idle/pause/play overlay today), chrome **frame times inherit the same publish jitter**. Edges become period-1 sharp; **swap/hold cadence stays juddery** → **sharp but juddering**.

4. **If chrome is static for long periods** (PAUSED string held; only video swaps underneath), chrome plane is temporally quiet and looks fine — but **video judder remains**, and any chrome that animates (timeline, spinners) reintroduces the interval process.

5. **Post-ascal plane does not touch** `swap_pending` / `pending_ready_s2` / `present_cadence` (which does not drive DDR swaps). It cannot repair content hold statistics.
