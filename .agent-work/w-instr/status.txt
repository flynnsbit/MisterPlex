1) span_rate contradiction (RULE 0 — resolved with code evidence)
----------------------------------------------------------------
Same /tmp/capboot, unique_ratio stable 0.8191, span_rate 0.7982 → 0.5321.

CAUSE (intentional but wrong estimator, not src_fps alone):
  Commit 48e9f2fd introduced analyze_counter_rate preferring:
    ctr_span = last_third_median(ns) - first_third_median(ns)
  On a linear ramp that equals (5/6 - 1/6) = 2/3 of true endpoint span.
  0.5321/0.7982 = 0.6666 exactly.

BEFORE (48e9f2fd / 2675c2b4 era):
  ctr_span_med = last_med - first_med
  if ctr_span_med > 0: ctr_span = ctr_span_med   # won on good ramps
  span_rate = ctr_span / cap_span

AFTER (2bbdffd4 + current):
  ctr_span = ns[-1] - ns[0]   # endpoints after outlier filter
  endpoint_rate = ctr_span / cap_span
  # never max-min (OCR dip inflate); never third-medians (2/3 bias)

explain a 33% drop in the measured span. The formula change does.
