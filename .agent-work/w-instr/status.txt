## PRE-REGISTERED PREDICTIONS (before parent long capture)

P1. On a healthy 480p 24fps clip, long capture (≥3 min, --src-fps 24/1, measured cap):
    frames_lost_adj ≈ 0, lost_frac_adj < 0.02, skip_status=SKIP_OK, conf=HIGH.
    HIT/MISS: parent publishes after run.

P2. If user-visible drops are real at the display:
    frames_lost_adj grows roughly linear with wall time; lost_frac_adj stable >0.05
    → skip_status=SKIP_LOSS conf=HIGH. Daemon drops/av_drift_ms may stay near 0
    (inadmissible by construction).

P3. Short bursts (ctr_span < 60): skip_status=SKIP_UNSCORED conf=UNSCORED —
    refuse a defended loss number. Existing ~5s labs are conf=LOW at best.

P4. cap_fps from PNG mtimes on this grabber ≈ 30–31 (already measured on
    capboot/cap480q/cap480b). If parent switches mode to 60, expected=src/cap
    becomes ~0.4 and rate gates move with the measurement — not a hardcoded 30.

P5. RLE-only lost_frac ~0.12 on known-good short bursts is mostly OCR misses
    of intermediate n (adjacent_lost=0). Trust frames_lost_adj, not frames_lost_rle.

## Delivered

### 1. Skip / jump detection (pixels only)
- skip_metrics: frames_lost_adj (PRIMARY), frames_lost_rle, hist, lost_frac, conf
- Arithmetic printed on every run (skip_arithmetic=...)
- ADJ: max_exp=max(1,ceil(di*src/cap)); dn>+max_exp → lost += excess
  (+2 on adjacent capture = 1 lost; no plateau slack)
- conf: UNSCORED span<60 | LOW <200 | MEDIUM <600 | HIGH ≥600 source frames
- status: SKIP_UNSCORED | SKIP_OK | SKIP_SUSPECT (≥2%) | SKIP_LOSS (≥5%, MED/HIGH)
- Does NOT change main rc (measurement dimension). Short window → UNSCORED conf.

### 2. cap_fps MEASURED
- Auto: (n-1)/mtime_wall labelled cap=measured
- Better: --capture-wall-s from ffmpeg wall clock
- Also --cap-fps caller / --probe-capture container
- RATE_OK needs src=caller AND cap in {caller, measured, container}
- src DEFAULT_ASSUMED → rate=RATE_UNSCORED always

### 4. A/V SYNC — instrument does NOT exist yet; path is real

Grabber audio IS present on this host:
  arecord -l → card 0: MS2109 [MS2109], device 0: USB Audio
  /proc/asound/cards → 0 [MS2109]: USB-Audio - MS2109 (534d:2109)

Honest status: **no A/V sync instrument is implemented today.** Video-only
counter tools cannot see audio. Self-reported audio_s/wall_s/av-lock share
daemon blindness and are inadmissible as proof.

Recommended measured approach (parent owns hardware):
1. Add PMS asset "AVSYNC_CLICK" : white FLASH frame at known content time T
   paired with a 1 kHz click (or single sample impulse) at the same T.
   Burn-in TREK24 counter continues so video flash frame n is known.
2. Capture simultaneously:
   - video: ffmpeg v4l2 → PNG/MJPEG
   - audio: arecord -D plughw:0,0 -f S16_LE -r 48000 -c 2 out.wav
   (confirm device: `arecord -l`; card index may move — prefer plughw:MS2109,0)
3. Detect:
   - video flash: frame where mean luma jumps (or counter n at flash)
   - audio onset: first sample energy above noise floor near expected time
4. av_skew_ms = 1000 * (t_audio_onset - t_video_flash)
   Bound with capture latency (USB MJPEG + ALSA) — characterise once with
   a loopback known-good path if available.

If ALSA open races the exclusive video device, capture audio in the same
ffmpeg graph when the MS2109 exposes an ALSA source alongside v4l2
(`ffmpeg -f v4l2 ... -f alsa -i hw:0 ...`).

## Parent capture commands (do not run here)

```bash
# Timed long soak (3+ min). Pass daemon fps= token. Wall-clock for cap_fps.
OUT=/path/cap480_long
mkdir -p "$OUT"
START=$(date +%s.%N)
ffmpeg -v error -f v4l2 -input_format mjpeg -video_size 1920x1080 \
  -i /dev/video0 -frames:v 5400 -y "$OUT/f_%04d.png"
END=$(date +%s.%N)
WALL=$(python3 -c "print($END-$START)")
echo "wall_s=$WALL"

python3 tools/hdmi_motion_instrument.py "$OUT" \
  --src-fps 24/1 --capture-wall-s "$WALL"
# expect: cap_fps_measure src=measured; skip_metrics conf=HIGH; publish HIT/MISS on P1/P2
# true rc:  cmd; echo "true rc=$?"
```
