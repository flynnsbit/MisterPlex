## TASK 2 — remaining 10 × +2 and grabber drops

### Does the instrument assume uniform capture spacing?
YES — stated explicitly now in skip_arithmetic and skip_notes:
  uniform_capture_spacing=ASSUMED
  di = cap_idx delta treated as di × (1/cap_fps) intervals.
  PNG sequence with only wall_s / n_frames for cap_fps cannot see a missing
  grabber sample: Δt≈2/cap between saved frames looks identical to a device
  +2 if you only have indices. This can inflate frames_lost_adj on every
  capture this project has taken. Parent: 2400/80.216=29.9068 vs 30.0
  ⇒ ~7.5 frame deficit over 80s, same order as the 10 +2 events.

### Discriminator: PTS-tagged capture
PNG f_%04d has no timestamps. Capture to MKV/NUT keeping v4l2 timestamps:

```bash
OUT=$HOME/misterplex-captures/pts_$(date +%Y%m%d_%H%M%S)
mkdir -p "$OUT"
# passthrough timestamps from v4l2; mkv stores pts
ffmpeg -v error -f v4l2 -input_format mjpeg -video_size 1920x1080 \
  -i /dev/video0 -vsync 0 -copyts -c:v copy \
  -f matroska "$OUT/cap.mkv"
# After session (or parallel limited frames):
ffprobe -v error -select_streams v:0 -show_entries frame=pkt_pts_time,best_effort_timestamp_time \
  -of csv=p=0 "$OUT/cap.mkv" > "$OUT/pts.csv"
# Extract PNGs WITH same order for OCR (or decode in-order):
ffmpeg -v error -i "$OUT/cap.mkv" -vsync 0 "$OUT/f_%04d.png"
# Pair: line i of pts.csv ↔ f_XXXX.png counter
python3 tools/hdmi_motion_instrument.py "$OUT" --src-fps 24/1 \
  --capture-fps 30  # or measured from PTS median Δ
# Then analysis entry (to be wired as --pts-csv next if needed):
#   for each adj +2 in counter domain, look at Δpts between those two PNGs
#   Δpts ≈ 1/cap_nom  (~33.4ms)  → device skip (source frame never shown long enough
#                                   OR never shown — still need n gap + short Δt)
#   Δpts ≈ 2/cap_nom  (~66.8ms)  → grabber drop (missing capture sample)
#   Δpts ambiguous     → UNSCORED for that event
```

Note: with 24fps content held 41.7ms and capture 33.4ms, a *displayed* source
frame cannot be entirely skipped under perfect uniform capture — parent arithmetic
accepted. So +2 with Δpts≈1/cap implies the source frame was on screen < one
capture period (possible with Drop present-skip). +2 with Δpts≈2/cap is grabber.

Better discriminator if available: same PTS path is the minimum; no ALSA needed.
