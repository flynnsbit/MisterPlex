5) Why L4 FPGA page cannot cause probe fail
================================================================
Probe does not map doorbell, does not read 0x3047F130 / 0x300FF130,
does not send PLXA. LAB "PLXJ=0x3047F130 L4" is host address math
printed BEFORE probe (main.cpp:652-662). It is not an ACK.

Idle/OSD threads (started before --play-file) may poke FPGA during
the probe window — first L4 log shows raster/OSD/idle BETWEEN the
LAB line and the wrapper. That is async workers, not setSourceAspect.

The only way L4 silicon is involved in this fail string is if
probe.valid and setSourceAspect ran. Those plays would print
ERROR media (publish failed or DDR layout) before the wrapper.

Unless the binary never reached setSourceAspect — which is exactly
!probe.valid.
