## Why this NAME (not a near-miss)
STATIC_NSS_GETADDRINFO_ABORT is the durable name because all four legs are
present in evidence:

1. **STATIC** — `make arm-plexd` uses `-static` (Makefile L631–681: "Fully
   static: MiSTer glibc is 2.31; modern toolchains need 2.32+ for dynamic.").
   W-arm-net file(1): `ELF 32-bit LSB executable, ARM, EABI5, statically
   linked, for GNU/Linux 3.2.0` bytes=16575060.
2. **NSS** — glibc `getaddrinfo` in a static binary `dlopen`s `libnss_*.so`.
   Those .so are the **box** glibc 2.31 modules, not the Arm GNU 13.2 libs
   used at link. Loader then calls `_dl_call_libc_early_init`; `sym == NULL`
   → abort. Canonical static+NSS death, not a DNS NXDOMAIN.
3. **GETADDRINFO** — W-arm-net ld note (required cite):
   `libavformat.a(url.o) ff_url_join: Using 'getaddrinfo' in statically
   linked applications requires at runtime the shared libraries from the
   glibc version used for linking.`
   FFmpeg net: `HAVE_GETADDRINFO 1` (`/tmp/ffmpeg-arm-u1-net/src/config.h:320`).
   `http.c:250` `ff_url_join(...)` → `url.c:56-57` `getaddrinfo` with
   `AI_NUMERICHOST`. Then `http.c:312-316` `ffurl_open` `tcp://host:port` →
   `tcp.c:186` `getaddrinfo(hostname, portstr, ...)` **without** a numeric-only
   bypass.
4. **ABORT** — r2-bbb24.log last line is the glibc fatal assert, not an
   avformat error string and not `network protocols disabled`.

Numeric PMS URL does **not** dodge this. PLAY host is already
`http://192.168.1.24:32400` (no DNS name). `ff_url_join` still calls
`getaddrinfo` to test IPv6 numeric form; `tcp.c` still calls `getaddrinfo`
to fill `addrinfo`. First `getaddrinfo` in the static image is enough to
trip NSS dlopen.

Not named otherwise:

- Not PMS-down (timeline GET via curl returned 200).
