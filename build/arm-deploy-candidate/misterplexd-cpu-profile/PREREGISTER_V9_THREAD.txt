B5 JIFFIES ACCOUNTING ARTIFACT (parent-flagged — treat seriously)
   Distinctions that separate artifact from real optimisable work:

   A) Dead-thread gap (visibility artifact of thread_cpu dump, NOT fake process CPU)
      process_dm - sum(live_tid_dj) ≫ 0 over the same window.
      Meaning: real CPU happened on threads that exited (often HTTP workers).
      Still real work — but fix is worker/churn path, not audio.
      Score as R2 not "fake".

   B) Fake / mis-attributed process CPU
      - HZ mismatch: reject if dc/(du*nproc) not ~100 (v7 check was ~100.1).
      - Children included: ffmpeg has separate pid (v7 same_fpid); if mpid threads

      - Clock accounting of blocked I/O: heavy MrAudio write() in kernel may
        appear as stime on T_audio. That IS real cost of our write pattern
        (optimisable: fewer syscalls, larger chunks) — count as real audio cost.
      - Double-count across samples: use one window, same pids, raw counters.

   C) Wall occupancy mistaken for CPU (already caught)
      pacing 23ms wall ≠ CPU. Any claim that uses wall buckets as CPU is invalid.

      FALSIFY large observer effect: process %onecpu under PROFILE=1 within ~10
      pts of 95.5 PROFILE=0 anchor (bounce2 also re-checks 113.9 vs 117.66).
      If PROFILE=1 process jumps to 120+, part of residual is instrumentation.
