# 720p24 RBF (fork of the v0.4.1 true480 QSF)

The glass-good **240p/480p** pair stays `Plex.qsf` / RBF md5 `07f54d9f`.
Do not change `clk_sys` on that file. 24 unique fps at **1280×720** needs a
sibling fit: `fpga/Plex_MiSTer/Plex_720p24.qsf`.

## Why a second QSF

| | true480 product | 720p24 fork |
|--|--|--|
| clk_sys | 20 MHz | **24 MHz** (`PLEX_CLK_SYS_24`) |
| Beam | 672×496 CE/2 → 30.0019 Hz | 1312×762 → **24.006 Hz** |
| Store | 624/618/640 @ `0x30000000` | 1280×720 @ `0x30180000` |
| Prefetch | 8 lines | 16 lines |
| 240/480 glass | production | **not this RBF** |

A 20 MHz L4 beam is 20.005 Hz (L47). Raising `clk_sys` on the 480p QSF would
break the proven 30.0019 Hz contract. Hence a fork, not a toggle on the
shipping file.

Restore `Plex.qsf` from git before any 480p rebuild.

## Fit slot720p24 (2026-08-12) — TIMING_FAIL, not deployed

| | |
|--|--|
| Wall | 993 s, Quartus Full Compilation **0 errors** |
| RBF | `e494a7671064a54f6d5d0ea274a762d0` |
| Hierarchy | PASS (`fstore` 192 M10K, `spath` 291 M10K / 33 DSP) |
| clk_sys | asked **24.0 MHz**, STA Fmax **13.77 MHz**, slack **−30.956 ns** |
| clk_ddr | asked 90 MHz, STA Fmax **75.66 MHz**, slack **−2.276 ns** |
| Deploy | **NO** — TIMING_FAIL ≠ BUILD_OK for glass |

Raising `clk_sys` is the wrong lever. Cyclone V is happy at 90–150 MHz on
pipelined domains (ao486 DDRAM 90 MHz, HDMI PLL ~148 MHz). This netlist put
1280-wide YUV store + `stream_path` decode on the **same** clock we then
asked to be the 24 Hz pixel clock. Fmax 13.77 MHz is that combo path, not
the FPGA.

Next RBF: keep product `clk_sys=20 MHz`. Put the 24 Hz beam on a **separate**
`clk_pix` (24.0 or 29.7 MHz) with a registered/FIFO crossing, like other
cores split CPU vs video PLL. Do not thrash-deploy `e494a767`.
