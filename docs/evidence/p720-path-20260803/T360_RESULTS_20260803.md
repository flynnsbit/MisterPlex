## 3) Detail vs motion — product judgment

| | 960×540 @24 (capped) | 640×360 @30 native |
|--|--|--|
| Source samples vs 720p | 0.5625× area | **0.25×** area |
| Scale to glass | 4/3 polyphase | **exact 2×** (replication) |
| Softness | moderate | **clearly softer** (blockier text/UI) |
| Cadence on 29.97 TV | PMS drop to 24 → **5:4 judder** | **native 30** |
| ARM budget @30 | FAIL −1.17 | **PASS +15** (est.) |
| Phase-index bug class | exposed on 4/3 path | **structurally immune** |

**Recommendation (both tiers, not either/or):**

```
source ≤25 fps (film)     →  960×540 + max_video_frame_rate=24   detail path
source ≥28 fps (TV/NTSC)  →  640×360 + no fps Extra              motion path
```

I **do not** recommend replacing 540 with 360 globally — film would pay a
permanent softness tax for a problem it doesn’t have. I **do** recommend 360 as
the correct **30 fps glass tier**, not a demotion fallback.

Helper shipped: `contentResolutionFor720GlassBySourceFps(hint)`.
Auto wire at play time is **not** default-on (metadata-before-URL ordering);
explicit:

```ini
# film / detail
DECODE=960x540
OSD_CONTROL=off
# max_video_frame_rate=24 is ladder default

# TV / motion
DECODE=640x360
OSD_CONTROL=off
# WEAK_BITRATE=1500 default; floor 1000
```

## 5) w-scaler / w-mem coordination

- **w-scaler:** exact 2× path is the prize (no 4-phase ROM). Content window
  **640×360** display lines (not 368).
- **w-mem:** payload **345600** fits legacy usable (520192) — Option-C **not**
  required for 360 alone. Selector must stay identity (fixed here). Do not
  revert `ddrFrameGeometryForFpgaPresent` to always-624.
- Bitstream ring future: SPS **368** if consuming coded coeffs.
