========================================================================
1. DERIVATION OF ~4037 paint_per_mb (frame 0 / IDR)
========================================================================

TB definition (tests/rtl/stream_path_full_frame_tb.cpp):
  paint_start = first fs_wr_reset after stub_busy rise
  paint_end   = first fs_swap
  paint_cycles = paint_end - paint_start
  paint_per_mb = paint_cycles / (mb_w * mb_h)

Measured (docs/evidence/plane_m10k_clip1_788aa5f.log):
  STAGE_CYCLES frame=0 parse_cycles=289 paint_cycles=1211072
               parse_per_mb=0.963 paint_per_mb=4036.907
  STAGE_CYCLES frame=1..11 paint_cycles=76800 paint_per_mb=256.000
               parse_per_mb≈1449..1497

Why frame0 ≠ pure present-paint
-------------------------------
decode_stub.sv PH_WAIT wait_done for IDR + ENABLE_DPB_REF_SEAM + use_real_ref:
  1) sets wr_reset_ptr <= 1'b1   (ALWAYS for non-P at wait_done)
  2) then overrides phase <= PH_I_RECON

So the FIRST fs_wr_reset is at the START of PH_I_RECON, not at PH_PAINT.
paint_end is still the end of diagnostic PH_PAINT (WxH @ 1 px/cy).

Therefore frame0 paint_cycles INCLUDES:
  A. PH_I_RECON   (full residual walk + sink FSM for all MBs)
  B. PH_DPB_FILL  (384 sample beats + mb_valid beat per MB, then deblock_ref_ready wait)
  C. PH_PAINT     (320*240 = 76800 exactly — matches frames 1..11 paint_cycles)

Arithmetic split (DPB rate from decode_stub PH_DPB_FILL: idx 0..383 then 384 mb_valid):
  diag_paint     = 76800
  dpb_approx     = 300 * 385 = 115500   (deblock_ref_ready wait NOT included — UNKNOWN extra)
  i_recon_est    = 1211072 - 76800 - 115500 = 1018772
  i_recon/MB     ≈ 3396 cy/MB
  paint_per_mb   = 4037 = (i_recon + dpb + diag) / 300

Dominant sink FSM phases for a full I16 MB (all 16 AC coded)
— counted from h264_i_res_recon_sink.sv state machine (strict, no overlap):

  phase              cy/MB     notes
  ------------------ ------    ------------------------------------------
  ST_MB_INIT           256     plane_y clear 1 we/cy (cnt 0..255)
  ST_I16_NB             48     top_row 16 samples × 3-cy issue/wait/capt (y>0)
  ST_I16_PRED          256     1 px/cy serial pred (shift-add plane)
  ST_HAD_WAIT          ~5      UNCERTAIN — Hadamard latency; small
  ST_HAD_PAINT         768     RMW pred+DC 3 cy/px × 256   *** large ***
  ST_IQ_WAIT ×16       272     serial DQ ~17 cy × 16 AC
  ST_APPLY_PX I16×16   768     RMW 3 cy/px × 16 × 16       *** large ***
  ST_MB_DUMP           788     256×3 read + TL save + 16 top_row we  *** large ***
  misc settle/start      ~5
  ------------------ ------
  sink model total    ~3163    (all-AC I16)
  vs i_recon/MB        3396    delta ~233 → traverse/RBSP/handshake (order-of-magnitude)

SINGLE MOST EXPENSIVE CLASS: 3-cycle RMW over plane_y M10K
  HAD_PAINT + APPLY_I16 + MB_DUMP ≈ 768+768+788 = 2324 cy/MB (~68% of sink model)

I4 path (when used): ST_I4_NB ~3 cy/sample neighbours + IQ 17 + APPLY 16 (1 cy/px, no RMW).

RBSP window load (traverse, not inside paint_per_mb for IDR after wr_reset):
  ~64–66 cy per window fill when walker needs bytes — charged to I_RECON wall time
  via res_blk backpressure, not a separate TB field.

========================================================================
2. OVERLAP vs STRICT SERIAL — measured from design
========================================================================

h264_i_res_recon_sink.sv:
  assign res_blk_ready = (st == ST_IDLE) && !write_busy && !pend_mb_end;

Traverse may only present the next residual block while the sink is ST_IDLE.
There is no dual-buffer of res_blk and no parse∥apply pipeline.

Consequence: naive sum of sink phase cycles ≈ wall-clock for the residual path.
P-frame STAGE_CYCLES "parse" is NOT pure CAVLC — see §1/§3 P notes.

5. CHEAPEST CYCLE RECOVERY (proposal only — not implemented)
========================================================================

Aim at the 3-cy RMW tax first (no new DSP; DSP hold 111/112).

Ranked by cy saved / expected ALM risk:

  A. Pipeline ST_MB_DUMP read (3-cy → 1 result/cy after fill)
     Save ~512 cy/MB (768→256). ALM: near-zero FSM tweak.
     Same pattern can apply to HAD_PAINT/APPLY issue/wait/capt.

  B. Eliminate ST_HAD_PAINT RMW: keep DC in regs; add ((dc+32)>>6) at
     ST_APPLY_PX and/or ST_MB_DUMP read path instead of rewriting plane_y.
     Save ~768 cy/MB. ALM: small (adder on dump/apply path already has tsum).

  C. Dual-buffer res_blk (accept next blk while APPLY runs)
     Does NOT reduce sink wall time for a single blk; hides traverse/CAVLC
     under APPLY when parse is the long pole. Helps P more than I16-all-AC.
     ALM: one blk coeff file + handshake (~low hundreds comb — PRE-REG before map).

  D. Do NOT re-parallelise serial IQ or serial I16 pred — undoes DSP/ALM wins.

Combined A+B on I16-all-AC sink model: 3163 − 512 − 768 ≈ 1883 cy/MB sink
  + ~233 traverse ≈ ~2116 still under 2667 (320 PASS) but still OVER 684 (480p).
  480p needs deeper cuts (fewer RMW on AC path, DPB coalescing per
  docs/p3-mc-dpb-bandwidth.md, or higher decode clock — clock change is
  integrate/SoC, not this lane).

6. P-FRAME NOTE (continuous playback)
========================================================================

For P + use_real_ref, wr_reset fires only when leaving PH_DPB_FILL toward
PH_PAINT (deblock_ref_ready_pulse path). So:
  parse_cycles ≈ full P MB walk + MC/store + DPB_FILL
  paint_cycles = diagnostic WxH only (256/MB)

Product-relevant continuous cost ≈ parse_per_mb ≈ 1484 (includes ~385 DPB/MB).
P-only compute rough: 1484 − 385 ≈ 1099 cy/MB if DPB stays in-window.
